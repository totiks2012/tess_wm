# tess_wm (wm-tview) — оконный менеджер модальных окон поверх tview

`tess_wm` — это TUI «менеджер окон» для **одного терминала**: поверх основного
приложения (tview) открываются **окна**, в которых живут либо интерактивные
`bash` (субпроцесс в pty + VT-эмулятор), либо произвольные tview-виджеты
(TextView, Table, List и т.п.). Окна сосуществуют, фокусируются, сохраняются и
восстанавливаются — как рабочие столы, только внутри одного Go-процесса.

Запускается как **метод `me`**: `me tess_wm`.

---

## Зачем это (коротко)

- **Всё внутри своей TUI.** Редактор + shell + git/diff в разных окнах, переключение хоткеем — не нужны tmux/zellij и чужие GUI-терминалы.
- **Не tmux.** Здесь окна — объекты процесса, а не отдельные терминалы; субпроцессы (bash) живут *внутри* окон. Рендер контролирует сам менеджер (VT-эмулятор `charmbracelet/x/vt`), а не внешняя программа.
- **Среда для `me`.** Методы `me` могут открываться как полноценные окна рядом с shell — долгий скрипт работает, пока ты переключаешься на другое дело.
- **Сессии.** Сохранил рабочее окружение (F7), перезапустил — всё поднялось заново в тех же директориях (F8 или авто-restore при старте).

---

## Запуск

```sh
me tess_wm        # метод me (реестр: ~/.config/me/me.conf)
```

При старте автоматически восстанавливается последняя сохранённая сессия
(`~/.config/wm-tview/session.conf`, либо `$WM_SESSION_FILE`).

**Автостарт в X11** (окно xterm, максимизированное): `/root/.local/bin/tess/l_tess_wm.sh`.

## Назначение клавиш — полный справочник

Обозначения: «промпт» = базовый экран/обводка окна/обычный вывод shell;
«полноэкранная TUI» = внутри окна запущена программа с alt-screen
(htop, mc, vim, less, …).

### Управление окнами

| Клавиша | Действие |
|---|---|
| `F2` | Новое **shell**-окно (каждое нажатие — ещё одно) |
| `F3` | Следующее окно (цикл по списку) |
| `F4` | Закрыть активное окно (до базового экрана; shell завершается) |
| `F6` | Демо-**окно-виджет** (tview.Primitive — в реальности сюда ставится любой виджет) |
| `F9` | **Обзор окон**: сетка живых миниатюр всех окон |

### Копирование / вставка (буфер обмена)

| Клавиша | Действие |
|---|---|
| `F5` | Режим выделения с клавиатуры (**copy mode**, как в tmux) |
| `Ctrl+Insert` | Копировать последнее выделение в CLIPBOARD |
| `Shift+Insert` | Вставить CLIPBOARD (fallback — PRIMARY) |
| Средняя кнопка мыши | Вставить PRIMARY (появившееся при выделении) |

> Требуется один из инструментов в `PATH`: `xclip`/`xsel` (X11) или
> `wl-paste`/`wl-copy` (Wayland). Без них вставка/копирование через буфер
> молча не срабатывают.

### Внутри copy mode (после `F5`)

| Клавиша | Действие |
|---|---|
| `↑ ↓ ← →` и `h j k l` | Движение курсора |
| `PgUp` / `PgDn` | Вверх/вниз на пол-экрана |
| `Home` / `End` | Начало / конец строки |
| `Space` | Закрепить начало выделения (якорь) |
| `Enter` | Скопировать выделение в буфер и выйти из режима |
| `Esc`, `q`, `F5` | Выйти без копирования |

Во время режима поверх окна видна подсказка, выделение инвертируется,
в заголовке окна появляется метка `COPY`.

### F-клавиши: политика (`F12`)

Для shell-окон F-клавиши димлема: их хотят и менеджер, и программы внутри.
Решается переключателем режима **F12** + автоматикой:

- **auto (по умолчанию).** На промпте и при обычном выводе F-клавиши — команды
  менеджера (F2…F9). Когда внутри работает полноэкранная TUI (htop/mc/vim/less —
  определяется по alt-screen), F-клавиши уходят **программе**. Команды менеджера
  в этом случае — через `Alt+Fn` (например `Alt+F4` — закрыть окно).
- **WM (режим, включённый F12).** F-клавиши всегда команды менеджера, даже
  внутри htop/vim.
- `F12` — **всегда** переключатель режима (перехватывается в любом случае).

Текущий режим виден в заголовке окна (`F12: auto` / `F12: WM`).

### Прочее

| Клавиша | Действие |
|---|---|
| `Ctrl+C` | Если окон нет — выход из приложения; если есть — уходит в активный shell |
| `F7` | **Сохранить сессию** (живой cwd каждого shell из `/proc/<pid>/cwd`) |
| `F8` | **Восстановить сессию** (закрыть всё, открыть заново: shell — в сохранённых директориях) |

## Обзор окон (F9)

Показывает все окна в виде живой сетки миниатюр (для shell — прореженный
рендер VT-буфера прямо в реальном времени).

| Клавиша | Действие |
|---|---|
| `↑ ↓ ← →` / `h j k l` | Перемещение выделения |
| `Enter` | Активировать выбранное окно, закрыть обзор |
| `Esc`, `F4`, `F9` | Закрыть без изменений |

## Сессии

- Файл: `~/.config/wm-tview/session.conf` (по умолчанию), переопределяется `$WM_SESSION_FILE`.
- Формат строки: `kind|cmd|path|name` (`shell|bash|/путь|shell` для shell-окна,
  `widget|||widget` — для виджета).
- Сохранение: `F7`; восстановление по хоткею `F8` и автоматически при старте.
- При нуле окон `F7` пишет **пустой** файл (сброс рабочего окружения).

## Интеграция с `me`

`me tess_wm` (зарегистрирован в `~/.config/me/me.conf`):

```
#@method: tess_wm
me tess_wm  ->  ~/.local/bin/me/me_lib/tess_wm.sh  ->  exec ~/.local/bin/tess/tess_wm
```

Если `me` переустанавливается (`install_me.sh`), блок метода нужно продублировать
в новый реестр — установщик перезаписывает активный конфиг.

Бинарь: `/root/.local/bin/tess/tess_wm` (идентичен `~/.local/bin/wm-tview`,
проектный — `/root/DEV/tess/prototype/prototype`).

Подробности разработки и история — в `/root/DEV/tess/README.md` и
`/root/DEV/tess/HISTORY.md`.
