# wm-tview — оконный менеджер модальных окон поверх tview (проект)

Проект «оконного менеджера» для одного терминала: слой поверх библиотеки
`rivo/tview`, который добавляет то, чего в tview нет — **много независимых
модальных окон, сосуществующих во времени**, с фокусом, переключением,
живыми субпроцессами и сохранением рабочего окружения.

Это **не фреймворк виджетов** (это делает tview), **не тайловый WM в терминале**
(это tmux/zellij) и **не делегирование рендера чужому GUI**. Это среда «всё
внутри своей TUI», завязанная на экосистему `me`.

Пользовательская инструкция: `/root/.local/bin/tess/README.md`.
Журнал решений и этапов: `HISTORY.md`.

---

## Что это и зачем

1. Основное приложение на tview (Root + виджеты).
2. Поверх него — оконный менеджер, который умеет создавать окна динамически,
   держать их одновременно, переключать фокус, буферизовать неактивные,
   закрывать по команде.
3. Содержимое окна — **либо** `tview.Primitive` (виджет), **либо** живой
   субпроцесс в **pty** (bash, скрипт, интерактивная программа) —
   долгоживущая сессия, с которой пользователь взаимодействует.

Сценарии:

- **Рабочая среда:** редактор + shell + git/diff в разных окнах, переключение хоткеем.
- **Мониторинг:** htop + tail логов + docker ps + свой скрипт — рядом.
- **Интеграция с me:** методы `me` как полноценные окна, а не одноразовые fzf-меню.
- **Отладка:** код + вывод тестов + shell для ручных команд.

Ключевое отличие в архитектуре — **мы владеем рендером**: в каждом shell-окне
работает VT-эмулятор (`https://pkg.go.dev/github.com/charmbracelet/x/vt@v0.0.0-20261012121731-67fa755d101a#section-documentation`), который рисует вывод pty
в регион окна. Поэтому окна — это объекты процесса, а не отдельные терминалы.

## Состав (проект-прототип)

| Файл | Назначение |
|---|---|
| `prototype/main.go` | Точка входа, tview-приложение, глобальные хоткеи, авто-restore сессии |
| `prototype/wm.go` | Менеджер окон: список `[]*Window`, активное окно, сессии, F9-обзор |
| `prototype/shell_window.go` | Окно-терминал: creack/pty + `charmbracelet/x/vt`, copy mode, буфер обмена |
| `prototype/overview.go` | Обзор окон (сетка живых миниатюр), навигация |
| `prototype/session.go` | Сохранение/восстановление сессии (`kind\|cmd\|path\|name`) |
| `prototype/*_test.go` | Юнит/интеграционные тесты (реальный bash, `-race`) |

Сборка бинаря:

```sh
cd prototype
go build -o tess_wm .
go build -o /$HOME/.local/bin/tess/tess_wm .   # установка для me
go build -o /$HOME/.local/bin/wm-tview .       # альтернативная цель
```

## Горячие клавиши (сводка)

Управление окнами:

| Клавиша | Действие |
|---|---|
| `F2` | Новое shell-окно |
| `F3` | Следующее окно |
| `F4` | Закрыть активное окно |
| `F6` | Окно-виджет (демо tview.Primitive) |
| `F9` | Обзор окон (сетка миниатюр) |

Буфер обмена / выделение:

| Клавиша | Действие |
|---|---|
| `F5` | Copy mode: `↑↓←→`/`hjkl` — курсор, `Space` — выделять, `Enter` — копировать, `Esc`/`q`/`F5` — выход |
| `Ctrl+Insert` | Копировать последнее выделение |
| `Shift+Insert` | Вставить CLIPBOARD (fallback PRIMARY) |
| Средняя кнопка мыши | Вставить PRIMARY |

Сессии:

| Клавиша | Действие |
|---|---|
| `F7` | Сохранить сессию |
| `F8` | Восстановить сессию (и авто-restore при старте) |

Политика F-клавиш:

| Клавиша | Действие |
|---|---|
| `F12` | Тумблер `auto` ↔ `WM`. auto: на промпте F-клавиши — менеджер, внутри полноэкранной TUI (alt-screen) — программе; команды менеджера тогда `Alt+Fn`. WM: F-клавиши всегда менеджера |

Полная таблица с пояснениями — в `/$HOME/.local/bin/tess/README.md`.

## Сессии

- Файл: `~/.config/wm-tview/session.conf` (или `$WM_SESSION_FILE`).
- Строка: `kind|cmd|path|name` — например `shell|bash|/tmp/opencode|shell`,
  `widget|||widget`.
- cwd shell-окна берётся живым из `/proc/<pid>/cwd` — `cd` в окне попадает в сессию.
- `F7` при нуле окон пишет пустой файл (сброс).
