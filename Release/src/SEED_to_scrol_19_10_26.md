Могу, но с одной честной оговоркой: я не нашёл в результатах поиска **подтверждения**, что `charmbracelet/x/vt` отдаёт scrollback-ячейки через `CellAt(x, y<0)` или через отдельный метод вроде `ScrollbackCellAt`. DeepWiki описывает `ScrollUp`/`ScrollDown` в пределах экрана и scroll regions, но не доступ к истории строк как к ячейкам . Один сторонний проект использует `emu.CellAt(x, row)` для видимой области, но про отрицательные `y` там ничего нет .

Поэтому твой SEED с блокером «сначала спайк API» — **правильный**. Я сохраняю этот блокер и добавляю в SEED ещё три уточнения, которые не дадут агенту «поплыть»:

1. **`MouseScrollUp/Down` — это `tview.MouseAction`, не `tcell.ButtonMask`.** В tview колесо приходит как `MouseScrollUp`/`MouseScrollDown` в `MouseHandler` . Это надо явно прописать, иначе агент начнёт копать `tcell.WheelUp`.
2. **TTY-детект через `readlink /proc/self/fd/0`.** Формула рабочая: `/proc/self/fd/0` — это симлинк на реальный файл (например `/dev/pts/2` или `/dev/tty1`) . Проверка на `/dev/tty[0-9]+` отделит чистую консоль от эмулятора.
3. **`EnableMouse` надо включать только в GUI.** В tview мышь по умолчанию выключена, включается через `app.EnableMouse(true)` . Если в TTY её не включать — мусорных escape-последовательностей не будет.

### Контекст и цель
Довести `tess_wm` до состояния абсолютного удобства без раздувания кода и оверхеда. Три улучшения:
1. **История вывода (Scrollback):** просмотр длинного вывода (`dmesg`, логи, `git log`) через VT-буфер.
2. **Максимизация рабочей области:** отступ строго в 1 ячейку по краям.
3. **Адаптивная мышь (TTY vs GUI):** автодетект окружения; в чистой Linux TTY — строго клавиатурный режим; в GUI-терминале — полная поддержка мыши, включая клик по миниатюрам в F9 Overview.

### Архитектурные требования и изменения

#### 1. Предварительная проверка API (Spike / Guard Clause) — ОБЯЗАТЕЛЬНО, ДО КОДА
- **Перед написанием основного кода** проверить API `charmbracelet/x/vt`:
  - Принимает ли `emu.CellAt(x, y)` отрицательные `y < 0` для чтения scrollback-истории?
  - Или есть отдельный метод (`ScrollbackCellAt`, `HistoryLine`, `ScrollbackLen`) для доступа к строкам истории?
- **КРИТИЧЕСКИЙ БЛОКЕР:** Если API библиотеки **НЕ** даёт точечного доступа к ячейкам scrollback для выделения текста в Copy Mode (F5) — **ОСТАНОВИТЬСЯ**, не додумывать, сообщить пользователю.
- **Если API есть** — зафиксировать точные имена методов в комментарии к коду и использовать их. Если API даёт только `Render()` строкой — scrollback в Copy Mode **невозможен**, остановиться.

#### 2. История вывода (Scrollback & Sticky Bottom)
- В `shell_window.go` увеличить буфер эмулятора до 2000 строк: `w.emu.SetScrollbackSize(2000)`.
- **В режиме F5 (Copy Mode):** навигация (`PgUp`, `PgDn`, `Up`/`Down`, `hjkl`) позволяет уходить в область scrollback (`Y < 0`, если API подтверждён спайком). `selectedTextLocked` корректно обрабатывает отрицательные Y.
- **Быстрый скролл без F5:**
  - `Shift + PageUp` / `Alt + k` — прокрутка вьюпорта вверх (`scrollOff`).
  - `Shift + PageDown` / `Alt + j` — прокрутка вьюпорта вниз.
- **Sticky Bottom:** При `scrollOff > 0` любой ввод с клавиатуры в **активное** shell-окно мгновенно сбрасывает `scrollOff = 0`.
- **Колесо мыши (только если мышь включена, см. п.4):** в `MouseHandler` shell-окна обрабатывать `tview.MouseScrollUp` и `tview.MouseScrollDown` (это `tview.MouseAction`, **не** `tcell.ButtonMask` ). Направление: `ScrollUp` → `scrollOff += 3`, `ScrollDown` → `scrollOff -= 3` (с clamp в `[0, ScrollbackLen()]`).

#### 3. Точная геометрия VT-окна (Max Geometry)
- В `wm.go` заменить `mw, mh := w*8/10, h*8/10` на строгую формулу с отступом в 1 ячейку:
  ```go
  mw, mh := w - 2, h - 2
  mx, my := x + 1, y + 1
  ```
  Это даёт максимальную полезную площадь при тонкой рамке `tview.Box`. Проверить, что при `w < 3` или `h < 3` не происходит паника (clamp: если `mw < 1` → `mw = 1`, аналогично `mh`).

#### 4. Детерминированный детект TTY vs GUI и мышь
- **Формула автоопределения (функция `isGUITerminal() bool`):**
  1. `os.Getenv("WAYLAND_DISPLAY") != ""` → **GUI (Wayland)**.
  2. `os.Getenv("DISPLAY") != ""` **И** `readlink /proc/self/fd/0` **НЕ** соответствует шаблону `/dev/tty[0-9]+` → **GUI (X11)**. (Симлинк `/proc/self/fd/0` указывает на реальный TTY-устройство .)
  3. Иначе → **чистый Linux TTY**.
  4. Дополнительный фильтр: если `screen.HasMouse()` возвращает `false` — мышь не включать даже в GUI.
- **В `main.go`:**
  ```go
  if isGUITerminal() && app.GetScreen().HasMouse() {
      app.EnableMouse(true)
  }
  ```
  (В tview мышь по умолчанию выключена . В TTY `EnableMouse` не вызывать вообще — тогда escape-последовательностей мыши не будет.)
- **F9 Overview (`overview.go`):** перехватывать `tview.MouseLeftClick` по ячейкам сетки. Клик по миниатюре — активировать окно и закрыть обзор. (Только если мышь включена.)
- **Shell-окно (`shell_window.go`):** `MouseScrollUp`/`MouseScrollDown` → скролл (см. п.2).
